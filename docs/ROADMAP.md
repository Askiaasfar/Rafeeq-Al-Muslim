# RAFEEQ — ROADMAP AND ACCEPTANCE CRITERIA

## Phase 0 — recover and preserve Bolt
Export code, archive original, inspect source/backend/database/auth/assets/routes/features/errors, export schema/data securely, and label each feature VERIFIED, PARTIAL, UI ONLY, PLANNED, BLOCKED or UNKNOWN.
**Exit:** reproducible backup and reliable inventory.

## Phase 1 — Lovable import
Import Bolt ZIP, reconfigure secrets securely, reconnect/migrate backend and database, compare screens/flows, connect GitHub to a dedicated code repository, and test staging.
**Exit:** imported build runs and preserves core behavior.

## Phase 2 — Quran foundation
Verified corpus, 114 Surahs, ayah counts, Juz/page mapping, RTL Uthmani rendering, search, translations/Tafsir provenance, bookmarks and reading progress.
**Exit:** content validation passes and reading works offline.

## Phase 3 — recitation/offline
Verified reciter/riwayah catalogue, playback/repeat, download manager, storage usage, cancellation/resume, checksums and airplane-mode playback.
**Exit:** downloaded resources demonstrably work offline.

## Phase 4 — worship
Prayer times with transparent settings, Adhan preferences/notifications, Qibla with calibration/manual fallback, duas and adhkar with sources.
**Exit:** tests across multiple locations/devices.

## Phase 5 — learning/library
Reviewed Tajweed curriculum, Hadith source attribution, Islamic library, progress and optional grounded AI explanations.
**Exit:** source review, content QA and AI limitations.

## Phase 6 — accounts/admin/Android
Secure account lifecycle, server-side roles, private owner dashboard, privacy/export/deletion policy, Android/PWA/native strategy, accessibility and device QA.
**Exit:** end-to-end auth/admin/privacy/mobile release tests.

## Release acceptance
No fabricated scripture/Hadith; no critical Arabic rendering defects; no secrets in repo/client bundle; no public admin access; no false offline claims; critical flows tested on real phones; backup/rollback tested; owner approves production switch.
